Decision 716 (meta, ledger row) answers b137-i as (a) and settles what typed it:
- The declared type of `syntax decl` is the contract the annotated declaration must meet. `unknown` gives `decl`
  no member (`decl.make` is the checker's refusal at the decorator); a behavior (`syntax decl: Module`) admits
  only a type implementing it — the annotation refused otherwise, naming type and behavior — and types `decl.make`;
  `fn(…) -> R` admits a function; `T` any declaration with its type kept.
- Every tree (init executor, addMember member) is type-checked once, at the decorator, by that type. 581 (2) and
  613 are amended: no longer "for each annotated declaration"; the splice stays the concrete declaration as code.
- `decl` is the declaration as code in a member as in an executor (613, 626, 627): `decorator-member-captures`
  and its `@Decl` text go; `decorator_member_captures_handle` becomes a run cell.
- New cells named in the row: `decl_unknown_no_member`, `decl_behavior_contract_refused`,
  `decl_behavior_member_typed`, `member_decl_as_code`. B-137's box has the line.
This lands in B-137's package (b642 or the tail, your call); rakun's 165 s10 decorators already write
`syntax decl: Module` / `Bean` where they call members, `unknown` where they only read `compiler.*`.
