# conversation-chat

The written conversation between the machines that build botopink and its maintainer. Nothing here is a
decision: a decision lives in `specs/1.0.12-beta/decisions-taken-steps.md` (its row) and `decisions-taken.md` (its subject's text) of the meta repository (`botopink/projects`),
and a question in its `decisions-pending.md`. This repository keeps the messages that lead there — the status
reports, the blocking factors, the answers, the decision digests — so that each side reads what the other wrote
without a chat window.

## One file per message

```
<directory>/<YYYYMMDD-HHMM>-<slug>-<id>.md
machine-2/20261018-2320-status-after-664-666-m2-0001.md
```

| Part | What |
|---|---|
| `<directory>` | the conversation the message belongs to: `machine-1/`, `machine-2/`, `machine-3/` (both directions with that machine), `all/` (the maintainer to every machine) |
| `<YYYYMMDD-HHMM>` | when it was written, the writer's local time; files sort by it |
| `<slug>` | three to six lowercase words with hyphens saying what it is about |
| `<id>` | the writer's short name and its running number, `m1-0007`, `m2-0012`, `m3-0001`, `mt-0031` — one sequence per writer, never reused |

## The head of a message

Every message starts with the same head, so the first lines say who writes, to whom and for what
([`TEMPLATE.md`](TEMPLATE.md), copied to start a message):

```markdown
---
from: machine-2              # machine-1 | machine-2 | machine-3 | maintainer
to: maintainer               # machine-1 | machine-2 | machine-3 | maintainer | all
purpose: report              # report | question | answer | digest | rule
subject: One line saying what this message is for
read: [ ]                    # the addressee turns it into [x] when it has read it; to `all`: m1 [ ] · m2 [ ] · m3 [ ]
in-reply-to:                 # optional — the file name of the message this one answers
---
```

- `purpose`: **report** — a machine's status in the four lines of `scripts/thread-rules.md` (Done, Running, Next,
  Blocking), every blocking factor named: a pending question, another machine's hash, the pool; **question** — one
  thing the writer needs decided, with its options; **answer** — a reply, each factor or question of the message it
  answers taken in turn; **digest** — decisions taken, what each changes for the reader; **rule** — a rule of the
  work, from the maintainer.
- `read`: the writer leaves `[ ]`; the addressee turns it into `[x]` when it has read the message and commits
  that — the one edit ever made to another side's message. A message to `all` carries one check per machine, in
  order, and each machine ticks its own. `scripts/unread.sh <side>` lists what a side has not read yet, exit 1 while
  something is unread; a side reads its unread messages before it writes.

The body follows the head. Hashes are welcome here (this is a log, not a spec); scratch paths (`.tasks/…`,
`/tmp/…`) are not.

## Rules

- English, like every file of the project.
- A message is never rewritten after it is pushed; a correction is a new message with `in-reply-to`.
- One commit per message or batch, `chat(machine-2): m2-0012 status after 674` / `chat(all): mt-0031 decisions
  675–680`, pushed to `feat` at once (`main` follows `feat`). No branches, no PRs, no hooks.
- `status.md` at the root is generated by `scripts/status.sh` — who owes a read, each conversation's last message, the
  questions without an answer, every message newest first — and is run before every commit, never edited by hand.
- The meta repository pins this one under `repository/conversation-chat`; the pointer is bumped when it is
  convenient, never a condition for a message.
